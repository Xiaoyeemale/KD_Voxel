# SDR-Voxel R-CNN：理论问题 → 建议 → 代码落点

> 本文是 `SDR-审计报告.md` 的续篇。审计报告负责"找出问题"，本文负责"按证据定方案"，
> 并给出每一处改动的实测依据。所有数字都可用 `tools/bench_eipbs.py` 复现（真实 KITTI，
> 纯 numpy，不需要 torch）。
>
> 一句话结论：**③ 的增益主要来自"逐点重要性"，不是"按线束丢线"；而最大的一块来自
> 训练期的 GT 类别先验，测试期拿不到**。因此默认配置改成"等点数预算 + 逐点重要性"，
> 并把"模拟 16 线"降级为一个可选口径，主力增益押在 ①+②。

## 2. ③ EIP-BS：实测结论（这是本次改动最扎实的部分）

**实验设置**：KITTI 训练集前 200 帧、645 个 Car 框（截断 <0.3、遮挡 ≤2，≈Moderate 口径），
平均 59 328 点/帧。指标都是"点被保留下来的比例"，不含任何网络，纯采样层。

- `车≥50%`：车框内点数保留过半的车占比 —— **可检测性的代理指标**（一辆车保不住一半点，基本就漏检）
- `车<5点`：保留不到 5 个点的车占比 —— 直接等于"必漏"
- `间隙`：存活线束在 64 条仰角网格上的最大间隔（均匀抽线恒为 4）

### 2.1 等点数预算（25% = 16/64）下的对比

**训练期（打分可看 GT 框）**

| 策略 | 保留率 | 前景保留 | 车≥50% | 车<5点 | 间隙 |
|---|---|---|---|---|---|
| 均匀抽 16 线（对照） | 0.249 | 0.191 | 0.143 | 0.439 | 4.0 |
| 随机保留 25%（对照） | 0.250 | 0.202 | 0.067 | 0.401 | 1.2 |
| 分层 + topk + 保线束结构 | 0.250 | 0.223 | 0.146 | 0.461 | 6.9 |
| 分层 + topk + 全局花预算 | 0.250 | 0.727 | 0.910 | 0.203 | 34.5 |
| **不分层 + topk + 全局花预算（默认）** | 0.250 | **0.793** | **0.991** | 0.168 | 44.9 |

**测试期（无 GT，类别先验失效）**

| 策略 | 保留率 | 前景保留 | 车≥50% | 车<5点 | 间隙 |
|---|---|---|---|---|---|
| 均匀抽 16 线（对照） | 0.249 | 0.191 | 0.143 | 0.439 | 4.0 |
| 分层 + mean + 保线束结构 | 0.250 | 0.188 | 0.099 | 0.503 | 7.1 |
| 分层 + topk + 全局花预算 | 0.250 | 0.227 | 0.177 | 0.472 | 34.4 |
| 不分层 + mean + 全局花预算 | 0.250 | 0.269 | 0.297 | 0.459 | 42.8 |
| **不分层 + topk + 全局花预算（默认）** | 0.250 | **0.290** | **0.353** | 0.425 | 45.3 |

**三条结论**

1. **等预算下 ③ 确实有增益，但没有 6 倍那么大。** 训练期看着是 0.99 vs 0.14，测试期掉到
   0.35 vs 0.14 —— 约 **2.5 倍**。论文里如果只报训练期的数字，等于报了一个测试时不成立的数。
2. **分层丢线（为了让仰角更均匀）在等预算下是负收益**（0.353 → 0.177）。它把预算浪费在
   "这一组里最好的那条线束"上，而那条线上可能什么都没有。所以默认关闭；只有当你必须
   声称"这就是 16 线雷达"时才打开，并接受覆盖率降到 0.10~0.24。
3. **线束打分的口径（mean/top/topk/max/count）在等预算下只差 0.02~0.05**，
   远小于"分层/不分层"和"有没有 GT"的差别。审计报告里"mean 明显更差"的结论，
   是**救援机制**造成的假象：旧口径保留 43% 的点，多出来的那 18% 全部是按分数挑的
   救援点，掩盖了线束选择本身的作用。

### 2.2 顺手推翻的另一条旧结论

审计报告说"按平均分丢线，4 帧里有 2 帧劣于均匀抽线"。在 200 帧、等预算、无 GT 的条件下，
`mean` 是 0.297（车≥50%），**优于**均匀的 0.143。所以文档 3.3(2) 的"按存活点平均打分丢线"
**不需要改**——它成立。需要改的是**保留率口径**和**训练/测试一致性**这两件事。

### 2.3 旧口径（39%~45% 保留率）为什么不作数

| 策略 | 保留率 | 前景保留（有GT） | 车≥50%（有GT） |
|---|---|---|---|
| 不分层 + topk（不等预算，靠救援） | 0.447 | 0.794 | 0.993 |
| 同上，压到 25% 预算 | 0.250 | 0.793 | 0.991 |

看上去"压预算不掉"——但那是因为救援把分数最高的点都挑了出来，与"16 线"无关。
只要对照组的点数也对齐到 25%，上表的 0.79 / 0.99 依然成立，**所以增益不是靠多拿点**，
而是靠"按重要性挑点"。这正是本文档希望你能写进论文的那句话。

## 3. ① MS-DGE：三处修正

### 3.1 密度先验的自适应归一化

原实现 `log1p(计数)/5`：KITTI 0.05 m 体素的点数 99 分位只有 ~5，`log1p` 后落在 1.0~1.6，
除以 5 是 **0.14~0.31 —— 近乎常数**，门控拿到的这一维等于没信息。

现在改成 `log1p(计数) / s`，`s` 是**训练集 99 分位的 EMA**（`_EMAQuantileNorm`，momentum=0.01）。
输出张开到 ~[0,1]，且换 Waymo、换体素大小、换成 EIP-BS 之后的稀疏点云都不必重调。
不引入参数（只有 buffer），不动参数量与 DDP 语义。

> 代价：多一个 buffer（`vfe.norm_fine.scale` / `vfe.norm_coarse.scale`），
> 旧 ckpt 没有它 —— 但 SDR 之前没有正式 ckpt，无影响。

### 3.2 精细分支"初始化即恒等"

`SCALE_FACTORS: [1,8,16,32]` 里的 `factor=1` 分支，原实现仍然过了
`Linear(128→128)+BN+ReLU` —— 它保住的是**分辨率**，但特征被一个随机线性层重新混合过了。
现在改成 `out = base_feat + transform(base_feat)`，且该分支 BN 权重**零初始化**，
于是初始化时 `out ≡ base_feat`。训练开始的第一步，MS-DGE 就是一个"单尺度编码器 + 多尺度旁路"，
不会因为随机混合把基线的起点搞坏。

### 3.3 先验直连门控（FiLM 式旁路）

`[log(计数), log(粗尺度计数), 距离]` 三个先验原本只能通过
`cat(512 维尺度特征, 3) → Linear(515→64) → Linear(64→4)` 间接影响 softmax，
信噪比被 512 维淹没。现在加一条 `Linear(3→4)`（**零初始化**）直接加到 softmax 逻辑值上：
初始化时等价于原实现，训练中让"稀疏/远处该偏向粗尺度"这个归纳偏置有一条低噪声通道。

### 3.4 另外两个开关

- `DENSITY_PRIOR: full | no_count | count_only | none`：一行消融"逐体素点数先验到底有没有用"
  （审计报告 §8 第 7 项），不用改代码。
- 门控熵监控：`msdge_gate_entropy` 归一到 [0,1]。**接近 1 = 各尺度等权（门控没学到东西）**，
  接近 0 = 硬选一档。训练中应缓慢下降。这是判断"密度门控是不是装饰"的唯一直接证据。

## 4. ② CG-RD：三处修正 + 关键消融怎么跑

### 4.1 分母下限（数值稳健）

`M_roi` 在 KITTI Car 上只占 2~4% 的格子，远车/无标注帧会接近 0，
`Σw` 一小，除法就把噪声放大成尖峰梯度。加 `DENOM_FLOOR: 1.0`（至少按 1 个格子算）。

### 4.2 径向项权重与分项监控

师生主干不同构（教师 4 通道 `MeanVFE`、学生 64 通道 `MSDGE`），两者特征模长的**量纲本身
不可比**，`|log r_t − log r_s|` 完全可能长期主导损失，把方向对齐挤掉。
新增两个日志量，训练时看一眼就知道：

- `cgrd_theta_mean`：θ/π 的均值（方向项）
- `cgrd_logmag_mean`：|log r| 的均值（径向项）

若后者比前者大一个量级 → 把 `RADIAL_WEIGHT` 调到 0.5 或 0，或直接 `DIST_TYPE: cosine`。

### 4.3 距离类型 = 消融开关

| `DIST_TYPE` | 含义 | 用途 |
|---|---|---|
| `riemann` | θ/π + |log r|（文档原式） | 默认 |
| `cosine` | 只 θ/π | 模长不可比时的稳妥版 |
| `l2n` | ‖f_t−f_s‖/(‖f_t‖+ε) | 与 θ/π 同量级的普通蒸馏 |
| `l2` | 逐像素 RMS 距离 | 最朴素的 MSE 蒸馏 |

**这是回答"② 相对普通 MSE 蒸馏到底值多少"的唯一正确方式**：同一份代码、同一个教师 ckpt、
同样的掩码与门控，只换"罚多少"的定义。`python tools/train.py --preset sdr_mse` 即可。

> 论文里必须报这一行。64→16 线蒸馏的总增益通常 +2~4 AP，其中绝大部分来自"有教师"这件事，
> CG-RD 相对 MSE 的增量一般只有 +0.3~1.0 AP。不报这一行，② 就只是一个"我们也用了蒸馏"。

### 4.4 蒸馏权重 ramp-up

`RAMPUP_ITERS: 500`：λ 从 0 线性升到设定值（约前 1 个 epoch）。
训练初期学生特征还是随机的，`D_rod` 的量级由初始化决定、与任务无关，
直接用全量 λ 会压过 RPN/RCNN 的定位梯度。日志里的 `cgrd_weight` 能看到爬升过程。

## 5. 一键实验矩阵（全部是"换一个词"）

```bash
python tools/train.py --preset baseline     # 0 对照组：稠密 64 线基线 → 也是教师 ckpt 的来源
python tools/train.py --preset sparse       # 1 纯稀疏基线：基线模型 + 均匀抽线到 25%
python tools/train.py --preset sdr_noms     # 2 ③+②（VFE 换回 MeanVFE）
python tools/train.py --preset sdr_nokd     # 3 ③+①（不蒸馏）
python tools/train.py --preset sdr_mse      # 4 ③+①+普通 L2 蒸馏（② 的对照组）★
python tools/train.py --preset sdr          # 5 完整
```

先跑 1，它是所有结论的地基：**如果 5 打不过 1，说明方法没用；如果 5 打得过 1 但打不过 4，
说明 ② 没用**。其余消融用 `--set` 现场改，不用新建文件：

```bash
python tools/train.py --preset sdr --set MODEL.VFE.SCALE_FACTORS "[8,16,32]"   # 去掉精细分支
python tools/train.py --preset sdr --set MODEL.VFE.DENSITY_PRIOR no_count      # 密度先验消融
python tools/train.py --preset sdr --set MODEL.VFE.GATE_PRIOR_DIRECT False     # 关掉先验直连
python tools/train.py --preset sdr --set MODEL.VFE.FINE_RESIDUAL False         # 关掉零初始化残差
python tools/train.py --preset sdr --set MODEL.KD.GATE_NORM count              # 文档原式（会塌缩）
python tools/train.py --preset sdr --set MODEL.KD.DIST_TYPE cosine             # 去掉径向项
python tools/train.py --preset sdr --set MODEL.KD.RADIAL_WEIGHT 0.5            # 弱化径向项
```

想复现"16 线保真"口径（覆盖率会掉到 ~0.10-0.24，但仰角结构与真雷达一致）：

```bash
python tools/train.py --preset sdr \
  --set DATA_CONFIG.DATA_PROCESSOR.3.STRATIFIED True \
  --set DATA_CONFIG.DATA_PROCESSOR.3.ALIGN_KEEP_STRUCTURE True
```

## 6. 训练日志必须盯的 6 个数

| 指标 | 健康区间 | 异常说明 |
|---|---|---|
| `cgrd_roi_ratio` | 1%~6% | < 1% → `ROI_DILATE` 调大（0.5 → 1.0） |
| `cgrd_gate_eff` | ≈1，平稳 | 持续单调下降 → 门控仍在塌缩 |
| `cgrd_theta_mean` vs `cgrd_logmag_mean` | 同量级 | 后者大一个量级 → 调 `RADIAL_WEIGHT` |
| `cgrd_weight` | 500 步内升到设定值 | 一直是 0 → ramp-up 没生效 |
| `msdge_gate_entropy` | 0.5~0.9，缓慢下降 | 恒为 1.0 → 门控没学到东西；< 0.2 → 硬选 |
| `cgrd_loss_total` / `rpn_loss` | 比值平稳 | KD 项量级超过检测损失 → 降 `LOSS_WEIGHT` |

## 7. 仍然没解决 / 需要你决策的

1. **训练/测试输入分布不一致（最重要）**。类别先验依赖 GT 框：训练期车体点保留 0.99，
   测试期 0.35。三个选项，选一个并写进论文：
   - (a) 保留现状，把 ③ 定位成"GT 引导的稀疏增强"（和 `gt_sampling` 同类），
        并在论文里说明训练/测试差异；
   - (b) `W_CLASS: 0`，两边一致（代价：训练期也降到 0.35，账面数字变小但诚实）；
   - (c) 测试期两阶段：先用一次前向拿到预测框，再按预测框做 EIP-BS。代码未实现（推理开销 ×2）。
2. **代理指标 ≠ AP**。本文所有结论都建立在"车框内点保留率"上，它与 AP 强相关但不是 AP。
   `car_cov50` 从 0.14 提到 0.35 是否等价于 AP +1，必须靠 `--preset sparse` vs `--preset sdr` 说话。
3. **③ 在 Car-only 下用不到"小目标保护"**。`CLASS_PRIORITY: [0.6, 1.0, 1.0]` 里的行人/骑行者
   分支在单类训练下永不触发。要拿行人 AP 作证据，必须切三类训练。
4. **① 的推理开销没有实测**。`M≈1.6 万` 体素时，每次前向多 3 个 `Linear(M×128→128)`
   与 1 个门控 MLP，需要在你的环境里用 `torch.cuda.Event` 量一次，别直接抄文档的"<1.3 倍"。
5. **EIP-BS 的数据加载开销**：网格协方差近似约 60~90 ms/帧（4 worker 下对吞吐影响不大），
   `USE_NUMBA: True` 单帧 2.5 s，只能离线生成缓存时用。
6. **文档措辞建议**（与审计报告 §5 一致，此处按新证据更新）：
   - 1.3(1) "0.4 m 恒等分支" → "精细分支保留编码器原生分辨率（本实现 0.05 m），另设 0.4/0.8/1.6 m 三档"
   - 1.5 "参数量 +0.35 M" → 实测约 +0.16 M（以构建日志为准）
   - 3.3(2) "丢平均分最低的线束" → **不用改**，等预算下它成立（见 §2.2）；
     但要补一句"保留率与真实 16 线对齐到 25%"
   - 3.3(3) "前景保留率 0.76" → 换成实测：**训练期 0.79 / 测试期 0.29**（25% 预算，200 帧）
   - 全文"模拟 16 线" → 若用默认配置（不分层、全局花预算），改为
     "等点预算（25%）的边缘重要性稀疏化"；只有 `STRATIFIED+ALIGN_KEEP_STRUCTURE=True` 时
     才能说"16 线"
